# wb-switch 版本介绍

> **通用模型源切换器** —— 把不同网关配置存成独立的「源」，图形界面一键切换；同一套源与组合，同时管理 WorkBuddy 与 Codex。
> 当前版本：**v2.3.0**

---

## 一句话看懂这次更新

**v2.3.0 把 wb-switch 从「WorkBuddy 专用工具」升级为「通用模型切换工具」**：新增目标工具（Target）适配层，同一套源 / 组合 / 网关可以写进 WorkBuddy 的 `models.json`，也可以写进 Codex 的 `config.toml`；针对 Codex 只认 Responses 协议而多数中转站只有 chat/completions 的矛盾，网关内置了双向协议翻译；同时所有自有数据搬进独立目录 `~/.wb-switch/`，不再往任何被管理工具的配置目录里塞文件。

---

## v2.3.0 更新详情

### 1. 多目标工具：WorkBuddy + Codex 一个界面来回切

- **侧栏顶部新增「目标工具」切换器**：点开下拉即可在 WorkBuddy / Codex 之间切换，列表里带每个工具的配置文件路径、安装状态与当前项勾选；切换后源列表、当前生效、备份页全部跟随（各自独立，互不影响）。
- **CLI 同样支持**：`wb-switch targets` 查看、`wb-switch targets use codex` 持久切换、`wb-switch --target codex <命令>` 临时指定（不落盘）。
- **每个目标一套独立数据**：源快照、备份、激活状态按 target 分目录存放；WorkBuddy 的 16 个源不会混进 Codex 的源库。

### 2. Codex 接入：任意 chat 上游都能用

Codex 的 `config.toml` 只支持 `wire_api = "responses"`，而绝大多数中转站只提供 `/v1/chat/completions`——直接改配置必然打不通。wb-switch 网关新增 `/v1/responses` 端点，**双向翻译两套协议**：

- **请求方向**：`input` / `instructions` / `tools` / `reasoning.effort` → `messages` / `tools` / `reasoning_effort`
- **响应方向**：`choices` → `output[]`（正文 / 推理 / 工具调用三类条目）
- **流式**：chat 的 delta chunk → `response.output_text.delta` 等 Responses SSE 事件
- **工具调用**：扁平 `tools` ↔ 嵌套 `function`、`tool_calls` ↔ `function_call`

切换到 Codex 后，工具只**定点**改 `model` / `model_provider` 与 `[model_providers.wb-switch]`，并给每个模型生成 profile 文件（`codex --profile <名称>` 切换）；用户原有的 `mcp_servers`、`notify`、注释**一个都不动**（实测 25 个表 → 26 个表，其余零改动）。

### 3. 数据目录独立：全部收进 ~/.wb-switch

```
~/.wb-switch/
├── current-target.json       # 当前目标工具
├── settings.json             # 全局设置
├── targets/
│   ├── workbuddy/            # profiles / backups / state / images
│   └── codex/                # 独立一套
└── gateway/                  # 网关（跨目标共享）
    ├── routes.json / health.json / gateway.pid
    └── logs/gateway.log
```

- 从旧版升级**自动迁移**：源、备份、设置、路由、日志全部搬进来，只补缺失、绝不覆盖，重复运行幂等。
- 迁移完成后旧目录（`<WorkBuddy根>/wb-switch/`）不再有任何读写，可安全删除。
- 修掉一个设计缺陷：网关 pid / 日志此前随 target 变化会在多个目录各存一份，现统一在 `gateway/` 共享目录。

### 4. 组合别名防混淆（延续自 2.2 末期）

模型组成员的别名自动带「组合名-」前缀（如 `mymix-glm-5.3`），不会与源内同名模型撞车；显式指定的别名依然尊重用户输入。

## 安装与升级

| 平台 | 产物 | 说明 |
| --- | --- | --- |
| macOS | `dist-app/wb-switch-2.3.0.dmg` | 拖拽到「应用程序」；无签名需右键「打开」 |
| Windows | `wb-switch-Setup-2.3.0.exe` / portable | 安装向导或免安装版 |
| Linux | `wb-switch-2.3.0.AppImage` / deb | 赋予执行权限后运行 |

**升级**：直接覆盖安装即可。旧版数据（源、备份、设置、路由）在首次启动时自动迁移到 `~/.wb-switch/`，一个不丢；确认无误后旧目录可删。安装后首次启动会自动更新内嵌 CLI 与 MCP 启动器。

---

## 验证要点（升级后自检）

1. **目标切换**：侧栏顶部「目标工具」下拉 → 切到 Codex，源列表应只显示 Codex 的源；切回 WorkBuddy，原有源和组合全部还在。
2. **Codex 真实调用**：网关运行中（`wb-switch gateway status`）→ `codex` 里发一条消息，确认 `provider: wb-switch` 且有回复。
3. **迁移核验**：`ls ~/.wb-switch/targets/workbuddy/profiles | wc -l` 应等于原有源数；旧目录已无新写入。
4. **切换闭环**：选一个源点「切换到此源」→ 生效卡变绿 → 重启目标工具（或新开对话）生效。
5. **安全兜底**：切换失败时磁盘配置自动回滚；Codex 的 TOML 只定点改三处，`codex doctor` 里 mcp_servers 应一切如常。
